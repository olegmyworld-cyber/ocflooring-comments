# 301 redirects — Semrush 4xx report, 29 Aug 2026

Source report: `nwocflooring.com_http_4xx_client_errors_20260829.csv` (23 URLs, all 404).

Two of the 23 were fixed at the source (see [Blog 404s](#blog-404s-fixed-at-source-no-redirect-needed)).
The remaining **21** are URLs that never existed under those paths — they need 301
redirects so crawlers and any external links land on the real page.

## How to add these

Webflow's Data API does not expose site redirects, so these have to be entered in the
Designer: **Site Settings → Publishing → 301 redirects**. Add the wildcard rules first,
then publish the site.

### Wildcard rules (covers 16 of the 21 in two lines)

| Old path | Redirect to |
| --- | --- |
| `/services-near-me/(.*)` | `/flooring-services-near-me/%1` |
| `/services/(.*)` | `/flooring-services-near-me/%1` |

## Still to fix: `OCAreasStart` uses the same wrong prefix

The `OCAreasStart` block in **Site Settings → Custom Code → Footer** compares
`location.pathname` against four paths that do not exist, so those four branches are dead
and the service pages never open the areas slider on their matching slide:

```js
if(p.indexOf('hardwood-floor-repair-in')>-1||p==='/services-near-me/flooring-repair')…
else if(…||p==='/services-near-me/floor-refinishing')…
else if(…||p==='/services-near-me/vinyl-plank-flooring-and-laminate-flooring')…
else if(…||p==='/services-near-me/hardwood-floor-installation')…
```

Fix: in that block only, replace the four occurrences of `'/services-near-me/` with
`'/flooring-services-near-me/`. This was left as a manual edit rather than applied via the
API — writing it back means replacing the entire ~10 KB footer block in one call, which
also carries the GTM noscript tag, the Swiper init, the nav and green-CTA scripts, and
retyping all of that to change four strings is not worth the risk to a live site.

The city-page branches (`hardwood-floor-repair-in`, `hardwood-floor-refinishing-in`, etc.)
are unaffected and work correctly today.

## Where the bad links come from

The `/services-near-me/*` and city-laminate links were not found in any CMS field, in any
page-level element tree that was checked, in the shared Navbar / Footer / Services / Areas
components, or in the site's freeform head and footer code. The most likely source is one
of the CDN-hosted registered scripts that inject link blocks — `OCAreaLinksInjector` (applied
site-wide), or the per-page `ocLaminateGuides` / `ocInstallGuides` / `ocRefGuides` /
`ocVinylGuides` / `ocBlogLinks` scripts. Their sources are hosted on
`cdn.prod.website-files.com`, which this environment's network policy blocks, so they could
not be read here.

The redirects above resolve the 4xx regardless of source. To also remove the bad links at
the source, read those scripts and apply the same `services-near-me` →
`flooring-services-near-me` correction.
